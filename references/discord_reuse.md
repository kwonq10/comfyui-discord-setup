# Phase 3（既存Botを再利用する場合）：設定の確認ガイド

> Claude Code への指示：
> - このファイルは「既存の Discord Bot を再利用する」とユーザーが選んだときだけ使う。**新規作成の手順（discord_setup.md）へは進まない。**
> - 最初に必ず次の注意をそのまま表示する：
>
>   **「今回は既存Botの確認だけを行います。設定を変更する必要はありません。Reset TokenやSave Changesは押さないでください。」**
>
> - R1〜R7 を **1回に1つだけ** 案内する。ユーザーが結果を伝えるまで次へ進まない。
> - R1〜R5 は画面を見るだけ。**スイッチ・チェックボックス・保存ボタン（Save Changes）・Reset Token を押させない。** 誤って変更した場合は「保存せずにページを閉じてください」と案内する。
> - 結果は項目ごとに次の4つで分類する（`check_bot_reuse.py summary` で一覧にする）。過去の記録（PROJECT_STATUS など）だけで分かることを「画面で確認済み」にしない。
>
>   | 分類 | 意味 |
>   |---|---|
>   | 画面で確認済み（screen_confirmed） | 今回ユーザーが画面で見て、期待どおりだった |
>   | 記録のみ（record_only） | 過去の記録にはあるが、今回は画面で見ていない |
>   | 未確認（unconfirmed） | 今回も記録でも分からない |
>   | 不一致（mismatch） | 画面で見た結果が期待と違った（**ここでは直さない**。理由と影響を説明し、変更するかは別工程でユーザーが決める） |
>
> - 通常モードでは、各項目の結果を `manage_progress.py fact bot_check_r1 screen_confirmed` のように記録できる（値は4分類のみ。名前やトークンは記録しない）。読み取り専用モードでは記録せず、会話内で保持する。

確認日：2026-10-29（画面名は Discord 公式ドキュメント docs.discord.com に基づく）

---

## R1. Bot がサーバーのメンバー一覧にいるか

1. **開くもの**：Discord アプリ（PC版）で、Bot を入れたサーバー
2. **クリックする場所**：画面右上の「メンバーリスト」アイコン（人の形）。一覧が既に出ていれば不要
3. **入力する内容**：なし
4. **正常な状態**：一覧に Bot（例：My ComfyUI Bot、名前の横に「アプリ」または「BOT」の表示）がいる。今は Bot を起動していないので **オフライン（灰色）で正常**
5. **完了後**：「いた」「いなかった」を伝える

> いなかった場合：招待されていないか、外された可能性。**ここでは招待し直さない**（不一致として記録し、対応は別に決める）。

## R2. Bot ページの Intents（特権インテント）を見る

用語：**Intent（インテント）**＝Bot が Discord から受け取る情報の種類。一部は「特権」で、Developer Portal で ON にしないと使えない。

1. **開くページ**：https://discord.com/developers/applications → 一覧から既存のアプリ（例：My ComfyUI Bot）をクリック → 左メニュー「**Bot**」
2. **クリックする場所**：なし（ページを下へスクロールして「**Privileged Gateway Intents**」を見るだけ）
3. **入力する内容**：なし。**スイッチに触らない。「Reset Token」「Save Changes」を押さない**
4. **正常な状態**：
   - **Server Members Intent**：ON
   - **Message Content Intent**：ON
   - **Presence Intent**：OFF（ImageSmith は使わない。ON でも動作はするが不要）
5. **完了後**：3つのスイッチの ON/OFF をそのまま伝える

> 理由：ImageSmith（`src/bot/imagesmith.py`）が `members` と `message_content` を要求する。OFF のまま Bot を起動すると、Discord が接続をコード `4014`（Disallowed intent）で切断する（公式：Gateway のドキュメント）。

## R3. Public Bot の設定を見る

1. **開くページ**：同じ「Bot」ページ
2. **クリックする場所**：なし（「**Public Bot**」の欄を見るだけ）
3. **入力する内容**：なし。**スイッチに触らない**
4. **期待する状態**：OFF（公式：OFF のとき Bot をサーバーに追加できるのは所有者だけ）
5. **完了後**：ON か OFF かを伝える

> ON だった場合：今すぐ壊れるわけではない（招待リンクを知った人が自分のサーバーに入れられる状態）。**ここでは変更しない。** 不一致として記録し、変更するかは別工程で決める（変更時は Install Link との組み合わせで保存エラーになることがある）。

## R4. Installation ページの Install Link を見る

1. **開くページ**：同じアプリの左メニュー「**Installation**」
2. **クリックする場所**：なし（「**Install Link**」欄を見るだけ）
3. **入力する内容**：なし。**選択肢を変えない・保存しない**
4. **期待する状態**：「**None**」（招待用リンクを公開していない）。「Discord Provided Link」でも動作には影響しないが、リンクを知った人が招待画面を開ける
5. **完了後**：表示されている選択肢を伝える

## R5. Bot のチャンネル権限を見る

1. **開くもの**：Discord アプリ → 生成に使うチャンネル（例：`#comfyui-generation`）の歯車（チャンネルの編集）→「**権限**」
2. **クリックする場所**：Bot（または Bot のロール）の名前をクリックして、権限の一覧を表示するだけ
3. **入力する内容**：なし。**チェックを変えない・「変更を保存」を押さない**
4. **期待する状態（目安）**：「チャンネルを見る」「メッセージを送信」「埋め込みリンク」「ファイルを添付」「メッセージ履歴を読む」が赤い×になっていない
   - この5つは **このSkillの推奨（最小の目安）で、1つずつの必要性は実機で検証していない**。既存Botは過去に動作実績があるので、×が無ければそのままでよい
5. **完了後**：×になっている項目があれば、その名前を伝える

## R6. トークンが PC に登録されているか（値は見ない）

- **読み取り専用モードでは行わない**（「未確認」として扱う）。
- 通常モードで、ユーザーが「登録の有無だけ確認してよい」と承認した場合だけ、Claude Code が次を実行する：
  ```
  python "${CLAUDE_SKILL_DIR}/scripts/check_bot_reuse.py" token-presence --consent-token-presence
  ```
  表示は「登録あり／未登録」だけ。値・長さ・先頭の文字は表示しない。
- **未登録だった場合も、Reset Token は案内しない。** まず「別の場所（以前のPC・別のユーザー）に登録していないか」をユーザーに確認する。再発行が必要かどうかは下の「トークンの再発行について」に従う。

## R7. ImageSmith の利用者・チャンネル制限（設定ファイル）

- 設定ファイル（configuration.yml）にはトークンが書かれている可能性があるため、**ユーザーが「設定ファイルを開いて制限だけ確認してよい」と明示的に同意した場合だけ** 実行する。同意が無ければ「未確認」。
  ```
  "<ImageSmith>\..\.venv\Scripts\python.exe" "${CLAUDE_SKILL_DIR}/scripts/check_bot_reuse.py" access-limits --file "<ImageSmith>\configuration.yml" --consent-read-config
  ```
- 表示するのはワークフローごとの「制限が有効か」「許可ユーザーの人数」「許可チャンネル名」だけ。ユーザー名・トークン・そのほかの値は表示しない。
- 自分のユーザー名が許可されているか確かめたいときは、ユーザーにユーザー名を入力してもらい `--expect-user <名前>` を付ける（結果は「含まれる／含まれない」だけ）。

## トークンの再発行について（このガイドでは行わない）

既存Botの再利用ルートでは **Reset Token を案内しない**。漏洩が疑われる場合（過去にスクリーンショットやチャットに写った等）も、自動で再発行を勧めない。必要な場合は **別工程として**、次をすべて説明したうえで明示的な承認を得る：

1. **理由**：なぜ再発行が必要か（どこに漏れた可能性があるか）
2. **影響**：Reset Token を押した瞬間に古いトークンは無効になり、起動中の Bot は切断され、古いトークンでは二度とログインできない
3. **再登録**：新しいトークンを PC に登録し直す必要がある（discord_setup.md の D5-b。チャットには貼らない）。別の場所（以前のPC等）で使っている場合はそちらも止まる

## 確認結果のまとめ方

```
python "${CLAUDE_SKILL_DIR}/scripts/check_bot_reuse.py" summary --r1 screen_confirmed --r2 screen_confirmed ... 
```
指定しなかった項目は「未確認」になる。全項目が「画面で確認済み」（R6・R7 は同意が無ければ「未確認」でもよい）で「不一致」が無ければ、「既存のDiscord Botが利用できるため、新規作成は不要です」と伝えて Phase 3 を終える。「不一致」があれば、内容を説明し、次へ進むか・別工程で直すかをユーザーに決めてもらう。
